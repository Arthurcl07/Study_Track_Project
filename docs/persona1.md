# Persona — Lucas Almeida (Formato de Regras)

## Regra P-01 — Perfil do usuário
- Quando o usuário for Lucas Almeida, o sistema deve reconhecer que ele é um estudante de Sistemas de Informação, com 20 anos, do 3º semestre.
- Quando o usuário for estudante em período noturno, o sistema deve considerar sua rotina de trabalho e estudo como fator de prioridade para organização e acompanhamento.

## Regra P-02 — Objetivo principal
- Quando Lucas acessar o sistema, ele deve conseguir acompanhar seu desempenho acadêmico de forma clara e rápida.
- Quando houver indicadores de notas, frequência e atividades, o sistema deve apresentá-los em uma visão consolidada.

## Regra P-03 — Acompanhamento de desempenho
- Quando Lucas consultar o dashboard, o sistema deve apresentar suas notas, médias, frequência e evolução acadêmica.
- Quando houver queda no desempenho, o sistema deve sinalizar a disciplina ou o indicador afetado.

## Regra P-04 — Organização de prazos
- Quando houver atividade acadêmica com prazo próximo ou vencido, o sistema deve informar Lucas sobre o prazo pendente.
- Quando uma atividade estiver atrasada, o sistema deve destacar esse status para evitar perda de pontuação ou reprovação.

## Regra P-05 — Identificação de risco
- Quando a frequência de Lucas em uma disciplina cair abaixo do limite aceitável, o sistema deve indicar situação de atenção ou risco.
- Quando houver múltiplas pendências, o sistema deve priorizar a visualização dessas condições no dashboard.

## Regra P-06 — Alertas acadêmicos
- Quando o sistema identificar risco de baixa performance, ele deve apresentar um alerta para Lucas.
- Quando o alerta for exibido, o sistema deve sugerir acompanhamento da disciplina e revisão de pendências.

## Regra P-07 — Evolução do estudante
- Quando Lucas consultar sua evolução acadêmica, o sistema deve mostrar tendências de desempenho ao longo do tempo.
- Quando houver melhoria ou piora, o sistema deve refletir essa variação em indicadores visuais.

## Regra P-08 — Facilidade de uso
- Quando Lucas acessar o sistema, a interface deve ser simples, objetiva e organizada em um único painel.
- Quando a informação for necessária, o sistema deve permitir acesso direto às principais áreas acadêmicas sem excesso de navegação.

## Regra P-09 — Cenário de uso
- Quando Lucas acessar o sistema e verificar que sua frequência caiu para 78%, o sistema deve apresentar a situação como atenção.
- Quando houver três atividades pendentes, o sistema deve evidenciar esses itens no painel principal.

## Regra P-10 — Benefício esperado
- Quando Lucas utilizar o StudyTrack, ele deve conseguir identificar dificuldades antes do fim do semestre.
- Quando o sistema apoiar a tomada de decisão, Lucas deve melhorar sua organização e reduzir o risco de reprovação.

---

## Resumo das regras
- Lucas precisa de acompanhamento simples e rápido do desempenho acadêmico.
- O sistema deve centralizar notas, frequência, atividades e alertas em um único ambiente.
- O sistema deve apoiar a identificação de problemas antes que se tornem críticos.
- O objetivo principal é ajudar Lucas a evitar reprovações e melhorar sua organização acadêmica.
